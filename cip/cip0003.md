## Decision (2026-10-10)

**Option A — Revive Poetry**, superseding [#1080](https://github.com/SheffieldML/GPy/pull/1080)
with a maintainer PR on current `devel` (do **not** merge #1080 as-is).

Policy locked at Accept (override only via CIP update):

| Topic | Decision |
|-------|----------|
| Tool | Poetry (`poetry-core` build backend) + Cython via `build_extension.py` hook |
| End users | Keep `pip install gpy` from wheels; Poetry is a **contributor** tool |
| NumPy | Align with current `devel` (`numpy>=2`); do **not** re-pin `<2` |
| SciPy | Required in `[build-system].requires` (for `cython_blas` cimports) |

| Dual packaging | Poetry becomes SoT; remove or stub `setup.py` / `setup.cfg` so they cannot diverge |
| Apple Silicon | First-class: CI must be green on `macos-latest` (Apple Silicon), or record an explicit deferral in this CIP before release |
| Related PRs | #1080 closed as superseded after the new PR merges; #1000 / #1031 folded into this plan and closed when absorbed |

## Summary

Migrate GPy's packaging and CI from a `setup.py`-centric workflow to
[Poetry](https://python-poetry.org/), with a PEP 517-style `pyproject.toml`, a
committed `poetry.lock`, a Poetry build hook for Cython extensions
(`build_extension.py`), and workflows that install and test via `poetry install` /
`poetry run pytest`.

The original work exists as open PR #1080 against `devel`. It never merged. This
CIP captures the intent, drift versus today's packaging reality, and the Accepted
Option A execution path via backlog tasks.

## Motivation

By mid-2024, dependency and PEP-related issues were stacking: NumPy / Matplotlib
compatibility reports, Cython extension builds, and inconsistent developer install
paths. Martin's stated goal was better dependency tracking and clearer
communication of compatible version ranges for contributors and CI.

Related open or adjacent work:

- [#1000](https://github.com/SheffieldML/GPy/pull/1000) — pep508 dependency specification
- [#975](https://github.com/SheffieldML/GPy/pull/975) — oldest-supported-numpy for build (**closed** as superseded)
- [#1031](https://github.com/SheffieldML/GPy/pull/1031) — Cython as setup-time, not runtime, dependency
- [#1006](https://github.com/SheffieldML/GPy/pull/1006) (merged) — partial move of metadata into PEP 621 `pyproject.toml`

## Detailed Description

| Area | Change |
|------|--------|
| Metadata / deps | New Poetry `[tool.poetry]` `pyproject.toml` (version pinned to `1.13.1` at the time) |

| Left in place | Existing `setup.py` / `setup.cfg` still present on the branch (dual packaging surface) |

### Declared dependency policy in the *original* PR (superseded by Accept table)

- Python `>=3.9,<4`
- NumPy `>=1.7,<2` — **do not revive**; `devel` and paramz now support NumPy 2
- SciPy version markers for Python 3.9 vs newer
- Cython listed under runtime Poetry dependencies — **move to build-only**
- `tables >= 3.9.0` as a hard dependency — **keep optional**
- Optional extras aligned with prior docs / notebook / plotting / mpi groupings
- Dev group: matplotlib, pytest, pods

### Drift versus current `devel` (as of 2026-10)

Addressed by Option A backlog (not by merging #1080):

1. NumPy policy — lift to `numpy>=2`
2. Package / version identity — match `gpy` / current version
3. SciPy in the build environment — add to `[build-system].requires`
4. Cython dependency class — build-only (#1031)
5. `tables` — optional extra
6. Dual packaging — remove / stub setuptools entry points
7. CI toolchain — Python 3.11–3.14, current Actions
8. Apple Silicon — prove green or explicit deferral
9. Lockfile — commit for contributors; document library install story
10. Stale merge base — clean re-implementation / rebase onto `devel`

## Backward Compatibility

- **End users** keep `pip install gpy` with wheels; Poetry is not required at runtime.
- **Contributors** use Poetry for editable installs and locked envs.
- Do **not** reintroduce NumPy `<2` or hard `tables` without a separate CIP update.
- Distribution name stays consistent with the PyPI project (`gpy`).

## Testing Strategy

- Matrix: Linux, Windows, macOS (Apple Silicon), Python versions supported by `devel` policy.
- Prove: `pip install` from built wheel; `poetry install` contributor path; `pytest GPy/testing`.
- Prove: Cython extensions import on each platform (`stationary_cython`, `choleskies_cython`, `linalg_cython`, `coregionalize_cython`, `state_space_cython`).
- Prove: isolated PEP 517 build with SciPy present for `cython_blas` cimports.
- Explicit acceptance criterion: **macOS Apple Silicon CI green**, or a written deferral in this CIP before release.

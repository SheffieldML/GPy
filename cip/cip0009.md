## Summary

Raise **meaningful** unit-test coverage on historically thin modules (especially
plotting backends), and set a lightweight process so Codecov **patch** reports
on PRs are actionable without blocking merges while `codecov.yml` keeps patch
status informational.

**Trigger:** [#1229](https://github.com/SheffieldML/GPy/pull/1229) (#1210
plotting modernization) reported **~4.2% patch coverage** (~46 uncovered lines)
despite a green full suite and ~55% project coverage.

## Motivation

### Diagnosis of #1229 patch gap

| Observation | Implication |
|-------------|-------------|
| Project coverage ≈ 55%, patch ≈ 4% | The *delta* is untested, not the whole tree collapsing |
| Large rewrite in `GPy/plotting/plotly_dep/` | Smoke test loads plotly and draws one scatter; most helpers (fill, contours, annotations edge cases, online backend) never run |
| `pca.plot_*`, `state_space` plot, `ssgplvm` plot helpers | Switched pylab → pyplot; callers/tests rarely invoke these plot methods |
| `initialize_latent('rand')` | Covered; not the Codecov problem |
| CI coverage job: Ubuntu / Python 3.12, `pytest GPy/testing --cov=GPy` | Same suite as PR tests; no plotly-heavy or image-plot path expansion |
| `codecov.yml`: patch/project **informational** | Flag is a signal, not a merge gate — still worth fixing for trust |

Root cause: **modernization touched cold plotting code** that the existing suite
only lightly exercises. Patch % falls when many lines change in those files
even if behaviour is unchanged for users who never call that API.

### Broader problem

GPy’s ~55% project coverage concentrates on kernels / models / inference. Plotting,
examples-adjacent helpers, and some util modules stay sparse. Future packaging /
plotting PRs will keep angry patch reports unless we add targeted tests (or
explicitly omit dead paths with rationale).

## Detailed Description

### Goals

1. **Hotspot backlog** — inventory lowest-coverage packages under `GPy/`
   (start with `plotting/`, then util/models plot helpers) from the Codecov
   project view or `coverage report --skip-covered`.
2. **Patch hygiene for plotting PRs** — for each plotting change, require at
   least one test that executes the changed branch (not only “import library”).
3. **Plotly backend suite** — extend `test_plotting.py` (skip if plotly absent)
   to cover: `new_canvas` / scatter / fill_between / bar / annotation path /
   `change_plotting_library('plotly_offline')` round-trip without
   `DeprecationWarning`.
4. **Matplotlib helper suite** — smoke `PCA.plot_fracs` / `plot_2d`, and a
   minimal StateSpace or SSGPLVM plot call where cheap.
5. **Policy (optional later)** — keep Codecov informational until a baseline is
   trusted; then consider a soft patch target (e.g. 50%) for `GPy/` only, with
   excludes for Cython `.c` / generated paths if needed.

### Non-goals

- Chasing 90%+ project coverage.
- Blocking merges on Codecov while CIP-0008 release work is in flight
  (`informational: true` stays until Accept says otherwise).
- Rewriting the entire plotting stack.

### Relation to other CIPs

- **CIP-0005** — lint/format discipline; coverage is complementary quality signal.
- **CIP-0007 / #1210** — deprecation/plotting modernization exposed the gap.
- **CIP-0008** — release pipeline should keep the coverage upload job; dry-run
  wheels are separate from unit coverage.

## Implementation Plan

1. **Baseline:** export current Codecov / `coverage xml` hotspot list into this
   CIP or a short backlog task under `backlog/infrastructure/`.
2. **Slice A (plotting):** tests for plotly_dep paths touched in #1229 + PCA /
   state_space plot smokes; aim to clear the #1229-style patch hole on a
   follow-up PR.
3. **Slice B (hotspots):** pick next 2–3 lowest-coverage pure-Python modules
   with clear APIs; add focused tests.
4. **Docs:** README or testing note — how to run `--cov` locally; what “good”
   means for a plotting PR.
5. **Optional:** tighten `codecov.yml` patch target once Slice A is green on
   `devel`.

## Backward Compatibility

Tests and CI config only; no user-facing API change.

## Testing Strategy

- New tests must pass with and without optional plotly (`pytest.importorskip`).
- Coverage job remains single-matrix Ubuntu 3.12 upload to Codecov.
- Success metric for Slice A: plotly_dep + touched plot helpers show
  substantial patch coverage on a dedicated PR (order-of-magnitude above 4%).

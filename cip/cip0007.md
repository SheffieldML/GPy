## Summary

Triage the **open GitHub issues** on SheffieldML/GPy the same way
[CIP-0004](cip0004.md) triages long-lived pull requests: cluster by theme, map
each cluster to an existing CIP or a backlog task, close tickets that are already
addressed on `devel`, and leave a clear next step on the rest.

**Release gate (2026-10-11):** no release until every *legacy* issue has a
disposition — convert to Discussion, fold into a summary tracking issue, decide
not to proceed, or address. Intentional summary trackers may remain open as the
work queue.

**Completion wave (2026-10-11):** disposed **193** open legacy issues into six
summary trackers (#1209–#1214) + Discussion #1215 (usage Q&A). See below.

## Motivation

GPy had **225 open issues** at first triage (median age ~7 years). Almost none
were labeled. Many were support questions, stale install failures against old
Python/NumPy, or bugs already fixed on `devel` but never closed.

## Detailed Description

### Disposition vocabulary

| Disposition | Meaning |
|-------------|---------|
| **Closable now** | Fixed on `devel`; comment + close |
| **Closable after confirm** | Strong evidence of fix; close with reopen invite |
| **Needs verify** | Theme overlaps recent fixes; smoke-test before close |
| **CIP-owned** | Fold into CIP-0003 / CIP-0005 (or release discuss) |
| **Backlog** | Real residual work; track under `backlog/` |
| **Summary issue** | Consolidate many tickets into one tracker; close children |
| **Close as support** | Usage/docs question → Discussions |
| **Needs info** | Stale need-more-info; close with reopen invite |
| **Not proceeding** | Explicit process/product no |

### Process rules

1. **Comment before close.** Cite this CIP and thank the reporter.
2. **Do not mass-close by age alone.** Prefer disposition vocabulary (#1029 rejected).
3. **CIP before new design.** Packaging CIP-0003; lint CIP-0005.
4. **Backlog for residual bugs/features** once the theme is clear.
5. **Support → Discussions** (#1215); do not keep eternal Q&A as issues.
6. **Summary trackers** are the intentional remaining open issues until done.

### Earlier slices (2026-10-10)

First backlog slice + closes (#1023, #791, #755, #742, #909); High/Medium October
residuals Done under CIP-0006-linked backlog. See git history / CHANGELOG.

## Implementation Plan

1. Land this CIP on `devel` via PR (explanation + map).
2. Accept CIP → continue comment/close slices in small batches.
3. **Completion wave:** create summary issues + Discussions; dispose all legacy opens.
4. Keep backlog tasks updated as summary trackers are worked.
5. Mark **Closed** when maintainers accept the tracker set as the sole remaining queue.

## Backward Compatibility

Triage and documentation only. Individual follow-up fixes keep their own
compatibility notes.

## Testing Strategy

For any issue closed as “fixed on `devel`”: confirm test or smoke check.
For summary queues: reproduce on current `devel` before coding.

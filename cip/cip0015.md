# CIP-0015: INLA-style hyperparameter integration for Laplace GP models

## Summary

Add an optional wrapper that integrates over GP hyperparameters for models using the `Laplace` inference method, following the INLA recipe: a Laplace approximation to p(f | θ, y) at each of a small set of θ values, weighted by an approximation to p(θ | y). The first version is a dense-covariance, GPy-native wrapper. It does not reproduce INLA's sparse-precision scalability.

## Motivation

GPy's Laplace inference fits one Gaussian at the latent mode for fixed θ, and θ is normally set by MAP or type-II maximum likelihood. This understates predictive uncertainty. In the prototype below, the latent predictive variance at test points rose by up to a factor of 1.7 once the lengthscale and variance were integrated out, and the predictive means moved by up to 0.2 on the latent scale. The change matters most away from the data, where lengthscale uncertainty dominates.

GPy already has the pieces: a Laplace marginal likelihood, hyperparameter priors, and (since commit `dae930d4`) a requirement that transform Jacobians enter the target density. What is missing is the layer that explores θ and mixes predictions.

## Detailed Description

Work in the unconstrained optimiser space u (GPy's `optimizer_array`), so positivity constraints become a smooth transform and a Gaussian approximation to p(u | y) is reasonable.

1. **Mode and curvature.** Optimise to the MAP u\*. Estimate the Hessian H of −log p(u | y) by central differences of the model gradient. Set L so that L Lᵀ = H⁻¹.
2. **Design.** Evaluate at points u = u\* + L z. Two designs are supported:
   - *Grid*: greedy outward exploration in z with step 1.0, dropping points more than 3 nats below the maximum. Suitable for up to about 3 hyperparameters.
   - *CCD*: centre, 2d star points at radius 1.1 √d, and 2^d corners (R-INLA's default for more hyperparameters).
3. **Weights.** w_k ∝ exp(−`model._objective(u_k)`), normalised. This is log p(y | u) + log p(u), including Jacobian terms for parameters that carry priors.
4. **Prediction.** For each u_k set the model parameters, call the existing `predict` or `predict_noiseless`, and combine with the law of total variance. This gives the mixture mean and variance, not a full mixture density.

### Design findings from the prototype

The prototype is `cip/cip0015/inla_prototype.py`, with a check against dense quadrature in `cip/cip0015/check_inla_prototype.py`. Setup: 25 Bernoulli observations, RBF kernel with LogGaussian priors on both hyperparameters.

| Method | Points | Max abs error, latent mean | Max abs error, latent variance |
|---|---|---|---|
| Grid | 34 | 0.052 | 0.101 |
| CCD | 9 | 0.068 | 0.599 |
| Dense 41×41 quadrature (reference) | 1681 | n/a | n/a |

Observations that shape the design:

- **Priors are load-bearing.** `log_prior` adds the Jacobian only for parameters with a prior. Without priors, the density is flat in u, which is improper and depends on the parameterisation. The wrapper should either require priors on all free parameters or warn loudly.
- **CCD is cheap but coarse on variance.** Its centre and star points reproduce means well, but the variance error is six times that of the grid at d = 2. We should treat CCD as the choice for d ≥ 4 only, and report the design in use.
- **Warm starts are disabled.** `Laplace.inference` overwrites its warm start with zeros (a `FIXME` in the source), so each design point runs a full Newton fit. Cost is the number of design points times one Laplace fit. Fixing the warm start would help this wrapper directly.
- **Gradients are used for the Hessian.** This relies on the Laplace gradient being accurate. Where the Hessian has a non-positive eigenvalue, the prototype floors the eigenvalue and flags it. The real implementation should raise or fall back to a diagonal scale.
- **Only moments are mixed.** Mixing full predictive densities (as INLA does for marginals) needs a per-point quantile or density interface that GPy does not currently expose uniformly.

### Open design questions

1. Should this be a new inference class, or a post-hoc wrapper around a fitted model? The wrapper leaves `GP.predict` untouched and avoids touching the optimisation path. A new inference class would integrate with `model.predict` but entangles θ integration with the likelihood-gradient machinery.
2. Where does it live: `GPy.inference.hyperparameters`, or `GPy.util`?
3. Should the log-marginal-likelihood correction terms from INLA (simplified Laplace, skewness corrections to the marginals) be in scope? We propose not for the first version.
4. Sparse precision structure (GMRF, SPDE) is out of scope. The result is hyperparameter-marginalised Laplace, not scalable INLA.

## Implementation Plan

1. Move the prototype to `GPy/inference/hyperparameters/inla.py` with a public class and docstrings.
2. Raise or warn when free parameters lack priors.
3. Handle indefinite Hessians explicitly.
4. Fix or bypass the Laplace warm-start `FIXME` and measure the saving.
5. Add tests: weights sum to one; mixture variance is at least the plug-in variance for the latent function; agreement with dense quadrature at d = 1 and d = 2 within a stated tolerance; Gaussian likelihood case where Laplace is exact.
6. Add a short notebook comparing MAP, INLA-style and HMC (via the existing sampler) on a small classification problem.

## Backward Compatibility

None. The wrapper is additive and opt-in; no existing class or default changes. Step 4 touches `Laplace.inference` and needs its own regression check.

## Testing Strategy

As in Implementation Plan step 5, plus an HMC comparison on one problem to check the hyperparameter posterior itself, not just the predictions.

# CIP-0013: Sparse linalg modes and LQ factorisation for VarDTC/FITC

> CIPs describe HOW to achieve requirements (WHAT). This CIP implements
> [REQ-0004](../requirements/req0004_sparse-linalg-modes.md). It ports the
> **shared design** recorded in GPc
> [CIP-0016](https://github.com/SheffieldML/GPc/blob/main/cip/cip0016.md)
> (§ Approximation vs sparse linear algebra) and the **LQ maths** from GPc
> [CIP-001B](https://github.com/SheffieldML/GPc/blob/main/cip/cip001B.md)
> (Seeger et al. 2017) into GPy’s sparse Gaussian inferencers.

## Summary

Add an orthogonal **`sparse_linalg`** knob on GPy sparse Gaussian
inference (`VarDTC`, `FITC`, scoped `DTC`), using the same tokens as GPc
(`lq` | `stable` | `legacy`), then implement the **LQ** path and make it
the default once gated.

Today’s VarDTC/FITC arithmetic (whitened features → form \(B=I+A\) →
`jitchol`) is the **`stable`** mode. **`lq`** replaces
Gram+Cholesky of \(I+AA^\top\) with an LQ (QR-of-transpose) of the wide
matrix \([I,\,A]\) (optionally \(y\)-augmented), with reverse-mode grads
via the Seeger §4.3 LQ adjoint. Do **not** invent `VarDTC_LQ` subclasses.

**Which requirements?** [REQ-0004](../requirements/req0004_sparse-linalg-modes.md).

## Motivation

1. **Shared vocabulary.** GPc already exposes
   `gpc.SparseGPRegression(..., sparse_linalg="lq")` and documents the
   wire field in CIP-0016. GPy still folds “which GP” and “which factor”
   into one hard-coded Cholesky path, so benches and interchange cannot
   name the mode.
2. **Stability.** Forming \(AA^\top\) squares the condition number of the
   whitened features. LQ of \([I,A]\) is the Seeger BLR trick already
   proven in GPc CIP-001B for collapsed VFE/DTC (and FITC).
3. **No zoo explosion.** Encoding LQ as new inference classes would break
   the CIP-0016 approximation ↔ `inference_method` map and force users to
   rewrite scripts.

## Detailed Description

### Design locks (from GPc CIP-0016 note)

| Axis | GPy surface | Tokens | Meaning |
|------|-------------|--------|---------|
| Approximation (model / bound) | `inference_method` class | `VarDTC`, `FITC`, `DTC`, … | Which sparse GP |
| Inducing-side factor | `inference_method.sparse_linalg` | **`lq` (default after cutover)** \| `stable` \| `legacy` | How \(B\) / \(A\) is factored |

```python
m = GPy.models.SparseGPRegression(X, Y, Z=Z)  # inference_method = VarDTC()
m.inference_method.sparse_linalg = "lq"       # default once LQ lands
# or:
GPy.inference.latent_function_inference.VarDTC(sparse_linalg="stable")
GPy.inference.latent_function_inference.FITC(sparse_linalg="legacy")
```

- Canonical tokens on write; case-insensitive on read.
- Read aliases only: `stablefactor` / `chol` → `stable`; `gram` → `legacy`.
- Exact GP / non-sparse methods: ignore or reject non-default.
- Interchange (when GPy speaks CIP-0016 YAML/JSON): top-level
  `sparse_linalg` string, orthogonal to `approximation`.

**Rejected:** `VarDTC_LQ` subclasses; putting `lq` under approximation
names; silently changing StableFactor/current maths without a mode flag.

### What GPy does today (= `stable`)

**VarDTC** (`var_dtc.py`): \(L_m=\mathrm{chol}(K_{mm})\); whitened
\(A\) from \(L_m^{-1}(\psi_1\sqrt{\beta})\) (or ψ₂ path); \(B=I+A\);
\(L_B=\mathrm{chol}(B)\); bound and grads through triangular solves.

**FITC** (`fitc.py`): \(L=\mathrm{chol}(K_{mm})\) via `pdinv`;
\(A = (L^{-1}U^\top)\sqrt{\beta_*}(\ldots)^\top + I\);
\(L_A=\mathrm{chol}(A)\).

That matches GPc **StableFactor** arithmetic (GPc CIP-0012), not LQ.

### LQ path (`lq`) — maths summary (GPc CIP-001B)

Keep whitening: \(A = \sigma^{-1} L_m^{-1} K_{nm}^\top\) (GPy layout /
precision scaling as in VarDTC today). **Stop** forming \(AA^\top\) and
`jitchol(I+A)`. Instead:

\[
W=\begin{bmatrix} I_M & A\end{bmatrix}
= L\,Q
\quad\text{(LQ / QR of \(W^\top\))}
\]

Optionally augment with \(y/\sigma\) so the Woodbury quadratic \(r^2\)
falls out of the same factor. Bound pieces:

- \(\sum_i\log|L_{ii}|\) (use absolute diag; sign-normalise for prediction)
- data-fit from \(r^2\) or \(Q_2 y\)
- DTCVAR trace / \(\|A\|_F^2\) terms **outside** the LQ (unchanged
  structure vs today’s VarDTC)

**Gradients:** reverse-mode through the LQ adjoint (Seeger §4.3), then
existing whitening / kernel cotangents. Do not re-derive Legacy
\(\partial/\partial C^{-1}\) forms. Reuse GPy `util.linalg` BLAS wrappers;
implement `lq_factor` / `lq_adjoint` as pure NumPy/SciPy (QR of transpose
is fine — NumPy has no `gelqf`).

**Cost:** \(\mathcal{O}(M^2(M+N))\), ~2× flops vs Gram+chol; better
\(\kappa\). GPc’s performance CoE shows paying for explicit dense \(Q\)
(`dorglq`) and dual-path Legacy work is expensive — GPy should:

- Prefer forms that need only \(L\) (and \(c\)/`r`) for the bound when
  grads allow it; materialise \(Q\) only when required.
- Never keep a second Legacy Gram path hot on every step.

**`legacy`:** optional Phase B. If implemented, unwhitened
\(A=K_{uf}K_{uf}^\top+\beta^{-1}K_{uu}\) + `pdinv`-style path for
cross-checks with GPc. If deferred, reject `legacy` with a clear error
until then (do not silently alias to `stable`).

### Scope

| In v1 | Out of v1 |
|-------|-----------|
| `VarDTC`, `FITC` (+ constructor / property) | SVGP / SVI multi-output variants |
| Homoscedastic Gaussian sparse regression | Heteroscedastic LQ (follow stable if already limited) |
| Uncertain-inputs VarDTC: LQ on the same \(B=I+A\) after ψ₂ whitening | PITC / PEP |
| Dual-path tests vs `stable` on CIP-0011-style cells | Changing default before gates are green |
| Docs + changelog token table | Full CIP-0016 YAML I/O (separate / later) |

`DTC` (historical): same knob if cheap; otherwise document “use VarDTC”.

### Default cutover, release ladder, and branches

Ship the mode **additively** first; flip the default only when gates are
green and in a release that is already framed as GPy2 prep — not in the
same drop that first exposes the flag.

**Branching (two lines; CIP-0008 stays tag-from-branch for publish):**

| Git branch | Version line | Policy |
|------------|--------------|--------|
| **`release/1.16`** | **1.16.x** | Classic / compatible. Additive APIs only; default behaviour matches 1.15; Cython retained. Bugfixes and docs for installs that must stay close to today’s GPy. Tag `v1.16.*` from here. |
| **`main`** | **1.20.x** (GPy2-prep; *not* `1.2.0` — that sorts below 1.15 on PyPI) | Radical line. LQ default flip, Cython removal (CIP-000E), other CIP-0010 readiness. Tag `v1.20.*` (or later 2.0) from here. |

Do **not** land breaking/default-changing work on `main` until
`release/1.16` exists and has absorbed the additive CIP-0013 merge.
Cherry-pick or merge **compat fixes** `release/1.16` → `main` when
needed; never merge radical `main` commits back into `release/1.16`.

| Release | Branch | `sparse_linalg` default | Cython (CIP-000E) | Role |
|---------|--------|-------------------------|-------------------|------|
| **1.16.x** | `release/1.16` | **`stable`** (= today’s VarDTC/FITC) | **Retained** | Additive: API + LQ behind the flag; bit-identical defaults |
| **1.20.x** (GPy2-prep) | `main` | **`lq`** | **Removed** | Default flip + Cython exit + readiness; `stable` escape hatch for “match 1.15 / GPc StableFactor” benches |

Concrete steps:

1. Land API with default **`stable`** on `main` (this PR), then merge
   that tip into **`release/1.16`** so both lines share the additive
   surface.
2. Cut **1.16.0** from `release/1.16` when ready (changelog; Cython
   still present).
3. On **`main` only**, after gates vs `stable` (CIP-0011 cells;
   optional GPc cross-check): flip default to **`lq`**, remove Cython,
   bump toward **1.20**; note in changelog.
4. REQ-0004 / this CIP close only with default `lq` on `main` and
   documented `stable` escape hatch (after the 1.20 cutover).

## Implementation Plan

1. **API plumbing**
   - Helper `GPy.util.sparse_linalg.parse_sparse_linalg(mode) -> str`
     (canonicalise + aliases).
   - `__init__(self, sparse_linalg="stable")` and property on `VarDTC`,
     `FITC` (and `DTC` if in scope).
   - Unit tests: default, set/get, aliases, reject unknown.

2. **LQ primitives**
   - `lq_factor(W)` → \((L,Q)\) with positive-diag convention (or
     abs-diag for logdet + signed \(L\) for reuse).
   - `lq_adjoint(L, Q, Lbar, …)` per Seeger §4.3; FD tests on random
     wide matrices (port spirit of GPc `testLQAdjoint` /
     `scripts/lq_sparse_prototype.py`).

3. **VarDTC `lq` branch**
   - After whitened \(A\) (existing code), branch on `sparse_linalg`.
   - `stable`: keep current `B=I+A; jitchol(B); …`.
   - `lq`: factor \([I,A]\) (and \(y\)-row if used); rewrite log-marginal
     and \(dL_dKmm\) / ψ grads through LQ adjoint + existing backsubs
     above the whitening.

4. **FITC `lq` branch**
   - Same token; LQ of \([I,\sqrt{\beta_*}V]\) analogue to GPc FITC LQ
     mode; keep `stable` as today’s `jitchol(A)`.

5. **Default flip (cutover release only — not ~1.16)**
   - Changelog + release note; default `"lq"`; document `stable` for
     “match GPy 1.15 / GPc StableFactor” benches.
   - Coordinate with CIP-000E Cython removal and CIP-0010 readiness so
     the cutover drop is one coherent GPy2-prep story.

6. **Interop / benches (light)**
   - Document token table next to sparse models docs.
   - Optional: record `sparse_linalg` in any GPy side of GPc
     `run_bench.py` comparisons.

## Backward Compatibility

- **Before default flip:** additive API; default `stable` preserves
  numerics and serialised behaviour.
- **After default flip:** LL/grads may differ in float noise and on
  ill-conditioned cells (intentional). Users pin
  `sparse_linalg="stable"` for bit-stable comparisons with older GPy.
- Pickle / `to_dict`: store `sparse_linalg` when present; missing key ⇒
  `stable` on load for old dicts, then follow library default policy
  documented in the flip commit (prefer explicit stored value once
  written).

## Testing Strategy

- Unit: parse helper; mode property; `lq_factor` / `lq_adjoint` FD.
- Model: VarDTC and FITC on well-conditioned toys —
  `|LL_lq - LL_stable|` tiny; gradient FD util comparable.
- Stress: crowded \(Z\) / large-\(N\) clustered cells inspired by GPc
  CIP-001B soak (document that crowded \(Z\) is \(K_{mm}\)-limited —
  LQ ≡ stable there).
- Optional cross-check: same data vs `gpc.SparseGPRegression(..., sparse_linalg=...)` when GPc is available.
- CIP-0011 suite: no new xfail; add mode-parametrised cases where cheap.

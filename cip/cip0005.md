## Summary

Adopt [Ruff](https://docs.astral.sh/ruff/) as GPy's primary linter and formatter through an *incremental* programme: start with a narrow, non-blocking configuration and pre-commit hook, then widen rule coverage and auto-fixes in small, reviewable steps. This CIP supersedes the stalled pylint/Codacy proposal (#863) and gives a design home for the ruff pre-commit work in #1103.

**Next step (Phase 3):** `F401` unused-import cleanup in package slices, then
remaining pyflakes / bugbear. CI **fails** on the configured `ruff check`
select (Phase 4 partial). Format `--check` still deferred. Phase 1
[#1148](https://github.com/SheffieldML/GPy/pull/1148); F821 [#1186](https://github.com/SheffieldML/GPy/pull/1186);
small F + lint enforce [#1188](https://github.com/SheffieldML/GPy/pull/1188).
Do **not** merge #1103 as a full-tree enable.

## Motivation

Martin Bubel's [#1103](https://github.com/SheffieldML/GPy/pull/1103) added a straightforward `.pre-commit-config.yaml` for `ruff` and `ruff-format`. Enabling it against the full tree immediately surfaced roughly 800 findings that need human attention (~255 files even with `--unsafe-fixes`). That volume is too large for a single PR and too risky to apply blindly when test coverage of stylistic and semantic edge cases is uneven.

Earlier, [#863](https://github.com/SheffieldML/GPy/pull/863) proposed pylint plus Codacy. That approach is heavier, platform-coupled, and has had no movement since 2021. Ruff is faster, is widely adopted in the scientific Python ecosystem, and can replace much of that stack if we adopt it deliberately rather than as a one-shot clean-up.

Without a CIP, packaging and triage discussions keep rediscovering the same choice: block contributors on a mass reformat, or leave linting unowned.

## Detailed Description

### Goals

1. Give contributors a single, documented lint/format tool (Ruff).
2. Avoid a repository-wide churn PR that obscures real fixes.
3. Keep CI useful: start advisory or narrowly enforced, then tighten.
4. Retire the pylint/Codacy proposal in favour of this path.

### Non-goals

- Perfect style compliance in the first merge.
- Reformatting Cython, generated, or legacy `old_tests` / `todo` trees in phase one.
- Mandatory Codacy or other hosted dashboards.

### Design: phased adoption

#### Phase 0 — Decision and baseline

- Accept Ruff as the lint/format standard (this CIP).
- Record a baseline: `ruff check` / `ruff format --check` counts on current `devel` with a documented config.
- Decide pre-commit is optional for contributors initially; CI may run `ruff check` in a non-blocking job first.

#### Phase 1 — Thin hook, wide ignores

- Land a `.pre-commit-config.yaml` similar to #1103, pinned to a current Ruff release.
- Add `ruff.toml` or `[tool.ruff]` in `pyproject.toml` with:
  - Explicit `target-version` matching supported Python
  - `exclude` for build artifacts, `.venv`, legacy trees as needed
  - A *small* select set (e.g. obvious bugbears / pyflakes) or a broad select with a large `ignore` list so CI starts near-green
- Do **not** enable format-on-save enforcement in CI until Phase 2.

#### Phase 2 — Format in bounded slices

- Apply `ruff format` per package slice (`GPy/testing`, `GPy/kern`, `GPy/models`, …), one PR each.
- Each slice PR: format-only commit, no behaviour changes; CI must stay green.
- After slices complete, enable `ruff-format` in CI.

#### Phase 3 — Turn on rule families gradually

- Enable rule groups in order of safety (e.g. pyflakes → bugbear → simplify → opinionated style).
- For each group: auto-fix where safe, manual follow-ups in the same or a paired PR.
- Prefer fixing forward on touched files over repository-wide archaeology.

#### Phase 4 — Harden

- Make pre-commit the documented contributor default.
- Fail CI on `ruff check` and `ruff format --check`.
- Close #1103 as completed-or-superseded once Phase 1 lands; close #863 as superseded by this CIP.

### Configuration sketch (illustrative)

Final pin versions and rule IDs to be chosen at implementation time:

```toml
[tool.ruff]
target-version = "py311"
line-length = 88
extend-exclude = ["GPy/old_tests", "GPy/kern/src/todo"]

[tool.ruff.lint]
select = ["E", "F", "W"]
ignore = ["E501"]  # widen/narrow deliberately per phase

[tool.ruff.format]
quote-style = "double"
```

### Risks

- **Unsafe fixes:** never bulk-apply `--unsafe-fixes` without per-slice review and tests.
- **Diff noise:** format slices must not mix with feature work.
- **Cython / generated code:** keep excluded until someone owns that path.
- **Contributor friction:** optional pre-commit until Phase 4 avoids locking out casual patches.

## Implementation Plan

1. Accept this CIP and mark #863 as intended-superseded (comment only when triage actions are approved).
2. Land Phase 1 config + pre-commit (derive from #1103).
3. Publish baseline counts in the CIP or a short backlog note.
4. Execute Phase 2 format slices as separate PRs.
5. Execute Phase 3 rule enablement as separate PRs.
6. Phase 4: enforce in CI; close #1103 / #863 with pointers here.

## Backward Compatibility

No runtime API impact. Git history will show large formatting commits; keep them merge-isolated and labelled so `git blame` remains usable (optional: `.git-blame-ignore-revs` for format commits).

## Testing Strategy

- Every lint/format PR must pass the existing pytest suite on CI.
- Phase 1 CI job may be `continue-on-error: true` until the selected rule set is green.
- No reliance on `--unsafe-fixes` without a dedicated review checklist.

## Related Requirements

None yet. Optional future requirement: "Contributors have a one-command lint/format path consistent with CI."

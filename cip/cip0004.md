## Summary

Triage the **long-lived** open pull requests on SheffieldML/GPy (everything open
*before* the October 2026 correctness surge). Cluster them, map each cluster to a
CIP or backlog item, close superseded noise, and leave a clear invitation on each
remaining PR so authors and maintainers know the intended next step.

The October 2026 correctness / serialization / likelihood batch is **out of
scope** here. It is documented retrospectively in **[CIP-0006](cip0006.md)**
([#1139](https://github.com/SheffieldML/GPy/pull/1139)): roughly #1124–#1147
(Raashish Aggarwal primary author of the fix PRs). Do not re-triage those PRs
under this CIP.

## Motivation

The open PR list had accumulated years of good-faith work with little disposition.
Leaving PRs open without a design owner creates false hope for authors, hides real
bugs behind merge conflicts, and duplicates effort (especially packaging). VibeSafe
gives us CIPs (HOW) and backlog tasks (DO) so community-driven review can resume
without pretending every stale branch is merge-ready.

### Process rules for this triage

1. **Comment before close.** Every close cites this CIP and thanks the author.
2. **Do not force-push contributor branches.** Prefer backlog tasks that re-implement or ask authors to rebase.
3. **Merge only after green CI on current `devel`.** Stale mergeable flags are not enough.
4. **One design owner per cluster.** Packaging stays under CIP-0003; lint under CIP-0005.
5. **Land CIP docs before mass comments.** Prefer CIP-0006 (#1139) and this CIP on `devel`, then execute closes/comments in small batches.

### First execution slice (high ROI)

1. Close superseded: #975, #1095, #868 (and #863 after CIP-0005 Accepted).
2. Comment on #938, #978, #1002 inviting rebase *or* maintainer re-implement.
3. Comment on #1103 pointing at CIP-0005 Phase 1 (not a full-tree enable).
4. Defer #1080 / Martin ping until CIP-0003 has an explicit Accept or Deferred decision.

## Summary

Triage the **open GitHub issues** on SheffieldML/GPy the same way
[CIP-0004](cip0004.md) triages long-lived pull requests: cluster by theme, map
each cluster to an existing CIP or a backlog task, close tickets that are already
addressed on `devel`, and leave a clear next step on the rest.

This CIP is the **issues** twin of CIP-0004. It does **not** re-open packaging
(CIP-0003), Ruff (CIP-0005), or the October 2026 correctness inventory
(CIP-0006); those remain the design owners for their clusters.

**First execution slice (already on `devel`, 2026-10-10):**

1. Added nine Proposed backlog tasks (commit `d62bc032`) for residual bugs,
   features, and docs that the October batch did *not* close.
2. Closed five issues as addressed: #1023, #791, #755, #742, #909.

This document records that slice and the recommended map for the remaining ~220
open issues so further closes and comments stay consistent.

## Motivation

GPy had **225 open issues** at triage time (median age ~7 years). Almost none
were labeled. Many are support questions, stale install failures against old
Python/NumPy, or bugs that the October 2026 batch already fixed on `devel` but
never closed.

Leaving them open:

- Hides real remaining bugs behind noise
- Duplicates CIP-0003 / CIP-0005 design discussions as one-off tickets
- Makes #1029-style “close everything old” tempting without a disposition map

VibeSafe backlog + CIPs give a better path: close what is done, own design under
CIPs, track DO work as backlog tasks, and move pure Q&A to Discussions when
useful.

### Disposition vocabulary

| Disposition | Meaning |
|-------------|---------|
| **Closable now** | Fixed on `devel`; comment + close |
| **Closable after confirm** | Strong evidence of fix; close with reopen invite |
| **Needs verify** | Theme overlaps recent fixes; smoke-test before close |
| **CIP-owned** | Fold into CIP-0003 / CIP-0005 (or release discuss); do not invent parallel design |
| **Backlog** | Real residual work; track under `backlog/` |
| **Close as support** | Answered usage/docs question; close or move to Discussions |
| **Needs info** | Already labeled; ping or close if stale |

### Process rules

1. **Comment before close.** Cite this CIP (or CIP-0003/0005/0006) and thank the
   reporter.
2. **Do not mass-close by age alone.** Prefer disposition from the vocabulary
   above (#1029 is not the process).
3. **CIP before new design.** Packaging and lint stay under CIP-0003 / CIP-0005.
4. **Backlog for residual bugs/features** once the theme is clear; promote to a
   CIP only if design forks.
5. **Support → answer + close** (or Discussions); do not keep eternal Q&A open.

- Confirm the relevant test or a one-liner smoke check on current `devel`
- Prefer reopen-with-script language over silent close when evidence is medium
